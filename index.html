PROBLEMS

既存のWikiはAI時代に対応できない

NotionやConfluenceのようなWikiシステムには、AIと共存する上で3つの構造的な問題があります。

⚠

信頼できる唯一の情報源(SSOT)がない

保存 = 即時反映の方式のため、組織内で合意が取れた正式なバージョンを担保する仕組みがありません。AIが作成途中のドキュメントや矛盾した情報を読み込み、誤ったアウトプットを生成するリスクがあります。

save === deploy
⚠

変更提案(Pull Request)の仕組みがない

変更が即時反映されるため、AIが自律的にドキュメントを編集した場合に、既存の正式なデータが汚染される危険があります。隔離された編集環境と承認フローが存在しません。

no isolation
⚠

意思決定の文脈が消失する

「いつ、誰が変更したか」という表面的な履歴しか残らず、なぜその変更が行われたのかという意思決定の背景が紐づきません。AIは文脈を含めた回答ができません。

context lost

SOLUTIONS

Lexisが提供するソリューション

AIネイティブな組織のために設計された、次世代のナレッジ基盤

☍ Branch

安全に編集できる
独立した作業環境

Gitのブランチと同様に、正式なドキュメント(main)を汚さず、独立した環境で安全に編集できます。AIにも隔離された環境を提供することで、自律的なドキュメント生成を可能にします。

  • ✓ mainブランチで正式版(SSOT)を保持
  • ✓ AI・人間それぞれに独立した編集環境
  • ✓ 3-way mergeによるコンフリクト解消
↷ Pull Request

変更提案と
承認フローを標準装備

編集されたドキュメントはPull Requestとして提出され、人間 + AIが最終的にレビューする仕組みを標準装備。意思決定の履歴がすべて記録されます。

  • ✓ 変更提案(PR)による承認フロー
  • ✓ コミットで意思決定の背景を記録
  • ✓ レビューコメントで議論を可視化
✎ Editor

誰もが使える
直感的なインターフェース

エンジニアはMarkdown、非エンジニアはブロックエディタで編集可能。Gitの知識がなくても、Notionのように直感的に操作できます。

  • ✓ Notionライクなブロックエディタ
  • ✓ ブロック単位のコンフリクト解消
  • ✓ GitHub / GitLabと連携
CI WORKFLOW

CIワークフローで品質を自動チェック

ソフトウェア開発のCI(継続的インテグレーション)の概念を導入。変更提案の提出時に品質を自動でチェックします。

check

ユビキタス言語チェック

組織内で統一された用語(ユビキタス言語)が、提出された変更提案で適切に使われているかを自動検知します。

⚠ "顧客" → "クライアント" に統一してください
⚠ "承認" → "アプルーブ" は非推奨です
warning

重複コンテンツ検知

提出された変更と既存ナレッジのコサイン類似度を算出し、内容が重複している場合にWarningを表示します。

⚠ 類似度 87% → docs/onboarding/guide.md
ℹ 既存ドキュメントとの統合を検討してください
pass

コンプライアンスチェック

特定の業界や規制に準拠しているかを自動でチェック。違反の可能性がある場合に即座に検出します。

✓ 個人情報保護法 → 準拠
✓ 社内セキュリティポリシー → 準拠

FAQ

よくある質問

料金はかかりますか？

いいえ。β版の期間中は無料でご利用いただけます。β版ユーザーに事前の断りなく課金することはありません。

機能や人数の制限はありますか？

β版のため、一部の機能は未実装・調整中です。ただし、編集 → レビュー → マージといったコアとなる体験は制限なくご利用いただけます。想定規模は小〜中規模チームです。

Gitの知識がなくても使えますか？

はい。LexisはGitの概念をメタファーとして活用していますが、実際の操作はNotionのようなブロックエディタで直感的に行えます。Branch、Pull Requestといった概念も、分かりやすいUIで提供しています。

フィードバックは必須ですか？

必須ではありません。使ってみて感じたこと（良い点も不満も）を教えていただけると、開発の参考になり助かります。

途中で使えなくなったりしませんか？

実運用を前提に開発しています。突然停止したりデータを失うことはありません（β版のため仕様変更が入る可能性はあります）。
